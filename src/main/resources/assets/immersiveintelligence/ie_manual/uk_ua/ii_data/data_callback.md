# scenario1
Спочатку [машина введення даних] (data_input_machine.md) надсилає наступний пакет до машини через [дуплексний з’єднувач] (data_wiring.md#duplexconnector).
|[data_packet]{}|
Особливістю цього з’єднувача є те, що він має різні кольори для входу та виходу, тобто мережа не буде захаращена пакетами, які намагаються дістатися до всіх кінцевих точок і потенційно порушують налаштування.
# scenario 2
Нарешті, щоб отримати [відповідь] від машини, було підключено [Debugger](data_wiring.md#debugger).
Вихідний пакет виглядає наступним чином:
|[data_packet]{}|
Змінні, що містили [запити], були замінені на [відповіді] на них. Один із запитів був недійсним (була помилка), тому було повернуто [нічого](data_types.md#null).
Тепер інженер повинен вирішити, що робити з цими отриманими результатами, *можливо, це початкова точка автоматизованої системи поповнення запасів?*
